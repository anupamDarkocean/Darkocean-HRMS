# Deployment Guide for Railway & Vercel

## Option 1: Deploy Backend on Railway + Frontend on Vercel (Recommended)

### Backend Deployment (Railway)

1. **Create a Railway project** at [railway.app](https://railway.app)
2. **Connect your GitHub repository**
3. **Add services:**
   - **PostgreSQL** — add from Railway's service menu (auto-injects `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`)
   - **Redis** — add from Railway's service menu (auto-injects `REDIS_URL`)
4. **Verify internal networking:**
   - Both Postgres and Redis should communicate over Railway's **private network** (no public exposure needed)
   - Railway auto-injects internal hostnames (e.g. `postgres.railway.internal`, `redis.railway.internal`) via the `PG*` and `REDIS_URL` env vars
5. **Set additional environment variables** in Railway dashboard:
   ```
   FRAPPE_SITE_NAME=site1.local
   ADMIN_PASSWORD=your_admin_password
   ```
6. **Deployment** is automatic — `railway.json` and `Dockerfile` handle everything

> **Note:** The entrypoint supports both Railway plugin vars (`PGHOST`, `PGDATABASE`, etc.) and manual vars (`DB_HOST`, `DB_NAME`, etc.). Railway's Postgres/Redis plugins inject the correct vars automatically on the internal network — no manual DB configuration needed.

### Frontend Deployment (Vercel)

1. **Go to [vercel.com](https://vercel.com)** and create new project
2. **Import from GitHub** — select the `dohrms` repository
3. **Configure settings:**
   - Root Directory: `frontend`
   - Build Command: `yarn build`
   - Output Directory: `dist`
4. **Set environment variable:**
   ```
   VITE_API_URL=https://your-railway-backend.railway.app
   ```
5. **Deploy**

## Option 2: Deploy Everything on Railway

If you prefer to keep everything in one place:

1. Create Railway project and connect GitHub
2. Add PostgreSQL and Redis services (they connect over the internal network automatically)
3. The `Dockerfile` will build and deploy everything
4. Set only `FRAPPE_SITE_NAME` and `ADMIN_PASSWORD` — DB/Redis vars are auto-injected

## Environment Variables

### Auto-injected by Railway (internal network):
```
PGHOST=postgres.railway.internal        # set by Postgres plugin
PGPORT=5432                             # set by Postgres plugin
PGDATABASE=railway                      # set by Postgres plugin
PGUSER=postgres                         # set by Postgres plugin
PGPASSWORD=<auto-generated>             # set by Postgres plugin
REDIS_URL=redis://redis.railway.internal:6379  # set by Redis plugin
```

### Manual (set in Railway dashboard):
```
FRAPPE_SITE_NAME=site1.local
ADMIN_PASSWORD=your_admin_password
PORT=8000                               # Railway usually sets this automatically
```

### Vercel Frontend:
```
VITE_API_URL=https://your-railway-backend.railway.app
VITE_APP_TITLE=Darkocean HRMS
```

## Database Setup

The entrypoint handles site creation automatically on first deploy:
1. Waits for PostgreSQL and Redis to be reachable on the internal network
2. Creates the Frappe site with PostgreSQL
3. Installs ERPNext and HRMS apps
4. Runs migrations

On subsequent deploys, it refreshes DB credentials from environment and runs migrations.

## Troubleshooting

**Error: "Invalid branch or tag: version-17"**
- The Dockerfile uses `FRAPPE_BRANCH=develop` (which tracks Frappe v17-dev)
- Do NOT override this to `version-17` — that branch doesn't exist

**Error: "PostgreSQL not reachable"**
- Ensure the Postgres service is running in Railway
- Check that it's connected to the same project (internal networking is project-scoped)

**Error: "Redis not reachable"**
- Redis is required for `bench migrate` — ensure the Redis service is provisioned
- Verify `REDIS_URL` points to the internal Redis hostname

**psycopg2 connection failures**
- Verify `PGPASSWORD` is set (check Railway's Postgres service variables)
- Ensure the Postgres service is on the internal network, not requiring public SSL

**Frontend not loading**
- Verify `VITE_API_URL` environment variable on Vercel
- Check CORS settings on backend

## Post-Deployment Steps

1. Access Railway backend URL
2. Create system admin user
3. Configure SMTP for emails
4. Set up backup strategy
5. Enable HTTPS (auto-enabled on Railway/Vercel)
